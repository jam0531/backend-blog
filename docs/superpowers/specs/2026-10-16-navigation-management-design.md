# 更多菜单管理设计

用户已确认并要求实现本方案：后台配置更多菜单；隐藏只移除入口，原页面网址仍能访问。允许设计独立菜单表，实际建表与初始化前必须再次确认。

## 范围

- 只管理相册 album、留言 messages、友链 friend-links、关于我 about、关于本站 about-web；首页、分类、归档、搜索不受影响。
- 页面路由继续由 Vue Router 静态登记。后台选择已有页面，支持新增菜单、改名、排序、显示/隐藏和删除配置；不动态执行组件路径，不生成页面，不管理后台路由。
- page_key 唯一，同一页面只配置一次。名称去首尾空格后非空，最多 64 字；排序 0～9999，按 sort_order、id 升序。
- 删除只操作菜单表，不删除页面或任何业务记录。隐藏不改变公开查询权限，也不影响页面内部的链接。

## 数据与接口

新增 site_navigation：id BIGINT（ASSIGN_ID）、page_key VARCHAR(32) 唯一、menu_name VARCHAR(64)、visible TINYINT、sort_order INT、create_time/update_time DATETIME。无外键，不修改现有表。

初始化五项名称、路径与现状一致，visible=1，sort_order=10/20/30/40/50。SQL 显式执行，不接入应用自动初始化；表已存在时建表失败，不覆盖。初始化种子使用固定 ID 1～5，后续 API 新增使用 ASSIGN_ID；所有 API ID 都输出字符串。

- GET /api/navigation：只返回可显示且在允许名单中的菜单。
- GET /api/admin/navigation：全部配置。
- GET /api/admin/navigation/pages：五个允许关联的页面。
- POST /api/admin/navigation：新增。
- PUT /api/admin/navigation/{id}：修改。
- DELETE /api/admin/navigation/{id}：删除配置。

管理接口沿用管理员会话和 CSRF；输入白名单，不接受客户端 ID/时间/路由路径。非法参数 400，重复页面 409，不存在 404。重复的并发请求由唯一索引兜底。公开只返回导航所需字段，禁用 HTTP 缓存以便刷新生效。

## 前端

后台 /admin/navigation，复用现有后台样式和离开未保存表单的提醒。名称、关联页面、自动展示的路径、排序、显示状态组成表单；列表展示全部配置及编辑/删除操作。全部页面已配置时提示可编辑现有项，不允许重复新增。

公开布局从接口生成更多菜单，按命名路由解析允许的 page_key，未知页面不显示。列表为空时隐藏整个更多入口。保存后刷新公开菜单状态；重新进入公开布局或刷新浏览器重新加载。不做实时推送。加载失败保留当前内存中最后成功结果，首次失败不展示更多，不恢复成写死的五项。

## 验证与约束

不创建、修改测试代码或脚本；采用现有离线编译、前端构建、临时内联 HTTP 查询和浏览器人工联调。依赖缺失则停止，不下载。现有业务表只读。

待确认数据库执行时说明：MySQL DDL 隐式提交，不能通过普通事务回滚建表；初始化单独事务，只写新表。创建后回退需另行确认，仅删除新表；不自动执行 DROP。真实写入验证也限定新表，完成后恢复五条初始配置。
